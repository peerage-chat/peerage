# Scope v1.0 (Android-only) + заявка NLnet

**Статус:** черновик к согласованию · **Дата:** 2026-06-27
Связано: [ROADMAP](ROADMAP.md), [SUBSYSTEMS](SUBSYSTEMS.md), [ADR-003 API движка](adr/ADR-003-engine-api.md).

## Цель 1.0 (одним абзацем)
Серверлесс E2E-мессенджер на Yggdrasil-mesh, которым приватный пользователь может
**пользоваться ежедневно на Android**: чат 1:1 и группы, звонки/комнаты, медиа в
чате (аватарки/картинки/файлы), офлайн-доставка, понятный онбординг с резервной
копией ключа — и **сильная анти-метаданная позиция** (PET-ось) + **анти-abuse**
(receiver-enforced бюджеты). Без своего сервера для данных (единственное внешнее —
опц. push-пробуждение). Открытый протокол, воспроизводимая сборка, готовность к аудиту.

**Платформа 1.0:** Android. Десктоп (Slint) — эталон/dev-инструмент, под релиз не
шлифуется (решение 2026-06-27) → ADR-001 (единый медиа-движок) откладывается.

## Что уже готово (рабочий scope)
Запускаемый serverless-MLS-мессенджер с двумя клиентами. Подсистемы:

- ✅ **Идентичность/крипто/vault** (ed25519→Yggdrasil/Curve25519, BIP39, NaCl Box, at-rest) — `core`.
- ✅ **Транспорт Yggdrasil** через FFI (без TUN/root, статический IPv6, обход NAT) + QoS-очереди.
- ✅ **Хранилище**: контакты (TOFU), история, профиль/настройки, at-rest.
- ✅ **Мессенджинг**: сессии, presence/keepalive, надёжная доставка (retry до Ack), anti-replay.
- ✅ **Группы MLS** (openmls) + serverless-упорядочивание (admin-sequencer) + онбординг по KeyPackage.
- ✅ **Медиа-движок** (не libwebrtc): Opus, H.264, RTP-lite, адаптивный джиттер; 1:1 аудио/видео, групповые звонки; «один в комнате» (кодек спит).
- ✅ **Комнаты**: маячок присутствия (Discord-style), instant-leave, TTL, мультипати аудио.
- ✅ **Android**: JNI-мост, Compose-UI (Главная/DM/меню/Сеть/группы — редизайн идёт), Camera2→MediaCodec zero-copy H.264, foreground-сервис (wakelock/wifilock), энергооптимизации.
- ✅ **Десктоп (Slint)**: функционально полный.
- ✅ **Security-аудит** ядра+десктопа (High/Medium/Low закрыты, dep-скан `deny.toml`). · GPL-3.0.
- ✅ **UI-язык**: тёмный Holo, квадратные аватарки+presence справа-снизу, Discord-сетка звонка.

Эквивалент усилия ≈ **8–15 человеко-месяцев** senior-разработки (плотность сложности
высокая; LOC ~13.5k — плохое мерило). **В заявке упирать на рабочий scope + demo, не на
человеко-часы** — грант финансирует ДЕЛЬТУ (ниже).

## PET-ось (анти-метаданные)
1. **Анти-трафик-анализ.** В 1.0 — **size-bucket padding** (тексты добиваются до
   фикс. размера, напр. 4 КБ) + унификация обрамления медиа-канала: по РАЗМЕРУ нельзя
   отличить «текст / большое медиа / звонок». В спеке ЧЕСТНО: защищаем размер, НЕ тайминг.
   Полный cover-traffic (скрыть «звонит vs молчит») дорог по батарее → **бэклог/research**.
2. **Авто-снятие метаданных** файлов (вкл по умолчанию). Надёжно — изображения
   (EXIF/GPS, ре-энкод); best-effort — документы; неизвестный бинарь — нельзя (честно).
   Живёт в пайплайне блобов (scrub до чанкинга).
3. **Sealed sender — research/бэклог, С ПОПРАВКОЙ.** Простое шифрование отправителя в
   payload НЕ скрывает его от Yggdrasil-транзита: src-адрес виден на IP-слое и является
   производной от pubkey отправителя. Настоящая sender-анонимность требует onion/mix-
   индирекции → крупно, post-1.0. В threat-model честно: скрыто содержимое payload, НЕ
   скрыты src/dst на сетевом уровне.

## Анти-abuse: бюджет ресурсов на пира (receiver-enforced)
**Констрейнт:** enforcement только на ПРИЁМНИКЕ — самоограничению отправителя в
открытом коде доверять нельзя.

- **Механизм:** token-bucket на источник (байты/сек + пакеты/сек) на ingress-цикле
  движка; превышение → дроп/пауза чтения/разрыв сессии. Отправитель обойти не может.
- **Анти-Sybil (ключевое):** лимиты **градуированы по доверию**, и для чужих бюджет
  **общий на весь класс**, не на личность. Контакты (verified) — щедро; известные —
  средне; **чужие (не в контактах) — одна мелкая ОБЩАЯ корзина на всех** (нагенерил
  1000 ключей → все черпают из неё). Sybil обнулён.
- **Унификация с репутацией:** это один примитив — «сколько ресурсов выдаю пиру X» =
  тир доверия + заработанная репутация (способ 1). Помогавшие пиры → бóльшие лимиты.
- **Слои-дополнения:** гейт «запрос в контакты» для незнакомцев (мелкий rate-limited
  запрос вместо флуда медиа); лимит хранилища офлайн-очереди на пира (по репутации);
  медиа уже receiver-driven (video `drop-on-full`, блобы — pull).
- **⚠️ Честный предел:** app-лимит защищает CPU/батарею/хранилище/app-трафик, но байты
  уже долетели до радио. Резать на радио = рвать Ygg-пиринг флудера (слой ниже). Полная
  защита = app-лимит + дисконнект Ygg-сессии. В threat-model записать.

### Унифицированные блобы (решение 2026-06-27)
Блоб = **один универсальный контент-адресный примитив** (BLAKE3-чанки, pull, возобновляемо,
лимиты размера/типа — анти-DoS) + тонкий **типизированный конверт** (mime/тип + метаданные).
Через него — аватарки, картинки, файлы, голосовые, стикеры. Сообщение ссылается на блоб по
хэшу. Одна подсистема → ~6 фич почти бесплатно.

## Гэп-анализ из идей-файла (a1cf4442) — решения владельца
**В 1.0 (дёшево-ценное):** LAN-апокалипсис (Ygg-мультикаст, выставить), audio-focus
(сотовый→mute), FLAG_SECURE (настр.), zeroize (RAM), active-speaker рамка (если движок
отдаст уровень звука), Argon2id-vs-Keystore выбор (в настройках at-rest).

**Решение владельца (1.0 или бэклог):**
- **Duress PIN** (тревожный → wipe + имитация краша) — сильная анти-принуждение, но
  капризная (случайный wipe, «имитация краша» хрупка). Дефолт — **бэклог**, если не решим иначе.
- **Offline BT/Wi-Fi-Direct** (свой транспорт ниже Ygg) — сильный resilience-нарратив,
  но реальная работа → **бэклог/research** (LAN-мультикаст в 1.0 ).
- **Sealed-sender (onion)** — см. PET #3 → **research/бэклог** с поправкой.

## Вехи под заявку (deliverables, формат NGI Zero)

- **M1 — Контракт движка + спека** (~4–6 нед). ADR-003 в код: `engine`-крейт,
  Command/Event, JNI-кодек; репатриация стата Сети + офлайн-TTL + презенс; **ingress-
  механизм rate-limit + дисконнект Ygg-сессии**. Спека протокола. *DoD:* клиент не
  считает домейн-логику; движок юнит-тестируется без устройства.
- **M2 — Унифицированные блобы + медиа в чате** (~7–9 нед). Крейт `blob` (BLAKE3, чанки,
  pull, лимиты/анти-DoS) + типизированный конверт; аватарки/картинки/файлы; **метадата-
  scrub**. *DoD:* приём/отправка картинки и файла; аватарки сверяются по хэшу; EXIF снят.
- **M3 — Офлайн/презенс + бюджет ресурсов** (~4–5 нед). SQLite-outbox + daemon; **бюджет
  ресурсов на пира** (rate-limit-тиры + локальная репутация способ-1 + storage-cap +
  гейт «запрос в контакты»). *DoD:* доставка после возврата; чужие на общей мелкой
  корзине; помогавшие — расширенный лимит/TTL.
- **M4 — Онбординг, ключ, настройки, верификация** (~4–5 нед). Первый запуск, резервная
  копия ключа (FLAG_SECURE), эмодзи-SAS, экраны настроек (энергия/медиа/хранилище,
  at-rest выбор Argon2id/Keystore, FLAG_SECURE-тумблер). *DoD:* регистрация+бэкап ключа;
  сверка по 6 эмодзи; настройки не захардкожены.
- **M5 — Анти-трафик-анализ** (~3–5 нед). Size-bucket padding + унификация каналов.
  *DoD:* размеры на проводе не различают текст/медиа/звонок; спека описывает границы.
- **M6 — Security-review** (~3–4 нед). `cargo-fuzz`+`proptest` на парсеры; Kani-харнессы
  (2–3 парсера); zeroize ключей; аудит блоб/ingress-поверхности. *DoD:* парсеры не
  паникуют ни на каком входе (CI); отчёт аудита.
- **M7 — Релиз-инженерия** (~3–4 нед). Воспроизводимая сборка, F-Droid, доки (спека,
  **threat model** с радио/sender-anonymity-пределами, build/run). *DoD:* воспроизводимый
  APK; страница F-Droid; сборка из исходников по доке.

**Итого ≈ 28–38 недель.** Потолок Entrust/Commons €50k, оплата по вехам (≈€6–7k/веха).
