# Scope v1.0 (Android-only) + заявка NLnet

**Статус:** черновик к согласованию · **Дата:** 2026-06-27
Связано: [ROADMAP](ROADMAP.md), [SUBSYSTEMS](SUBSYSTEMS.md), [ADR-003 API движка](adr/ADR-003-engine-api.md).

## Цель 1.0 (одним абзацем)
Серверлесс E2E-мессенджер на Yggdrasil-mesh, которым приватный пользователь может
**пользоваться ежедневно на Android**: чат 1:1 и группы, звонки/комнаты, медиа в
чате (аватарки/картинки/файлы), офлайн-доставка, понятный онбординг с резервной
копией ключа — и **сильная анти-метаданная позиция** (см. PET-ось ниже). Без своего
сервера для данных (единственное внешнее — опц. push-пробуждение). Открытый
протокол, воспроизводимая сборка, готовность к независимому аудиту.

**Платформа 1.0:** Android. Десктоп (Slint) — эталон/dev-инструмент, под релиз не
шлифуется (решение 2026-06-27) → ADR-001 (единый медиа-движок) откладывается.

## Что уже готово (рабочий scope)
Запускаемый serverless-MLS-мессенджер с двумя клиентами. Подсистемы:

- ✅ **Идентичность/крипто** (ed25519→Yggdrasil/Curve25519, BIP39, NaCl Box, at-rest vault) — `core`.
- ✅ **Транспорт Yggdrasil** через FFI (без TUN/root) + QoS-очереди — `transport`+ygg.go.
- ✅ **Хранилище**: контакты (TOFU), история, профиль/настройки, at-rest.
- ✅ **Мессенджинг**: сессии, presence/keepalive, надёжная доставка (retry до Ack), anti-replay.
- ✅ **Группы MLS** (openmls) + serverless-упорядочивание (admin-sequencer) + онбординг по KeyPackage.
- ✅ **Медиа-движок**: Opus, H.264, адаптивный джиттер-буфер, фрагментация; 1:1 аудио/видео, групповые звонки.
- ✅ **Комнаты**: маячок присутствия (Discord-style), instant-leave, TTL, мультипати аудио.
- ✅ **Android**: JNI-мост, Compose-UI (Главная/DM/меню/Сеть/группы — редизайн идёт), Camera2→MediaCodec zero-copy H.264, foreground-сервис (wakelock/wifilock), энергооптимизации.
- ✅ **Десктоп (Slint)**: функционально полный (чат/звонки/видео/экран/группы/настройки).
- ✅ **Security-аудит** ядра+десктопа (High/Medium/Low закрыты, dep-скан `deny.toml`).

Эквивалент усилия ≈ **8–15 человеко-месяцев** senior-разработки (плотность сложности
высокая: MLS-serverless, mesh-FFI, аппаратный видеокодек, два клиента; LOC ~13.5k —
плохое мерило для такой работы). **В заявке упирать на рабочий scope + demo, не на
человеко-часы** — грант финансирует ДЕЛЬТУ (ниже), не уже сделанное.

## Целевой фонд NLnet + тайминг

Линейка **NGI Zero** (финансируется Еврокомиссией): €5k–€50k, оплата по вехам,
обязательна свободная лицензия (GPL-3.0 ✓), лёгкая заявка. Различие фондов — тема:
- **NGI Zero Entrust** — privacy & trust enhancing (PET): приватность/безопасность. ← **наш основной прицел** (3 PET-вклада ниже).
- **NGI Zero Commons** — широкий «интернет как общее благо», децентрализованные приложения. ← запасной/совместимый.
- **NGI Zero Core** — ядро интернета (протоколы/инфраструктура). Менее точно для «приложения».
- **NGI Mobifree** — мобильная свобода (de-googled Android, F-Droid). Android-угол.

**Тайминг (проверено 2026-06):** общие callы СЕЙЧАС закрыты (Core/Entrust/Mobifree
завершены; Commons — 13-й финальный call 1 июня 2026). NLnet «подводит итоги
десятилетия NGI Zero и готовит переход к **Open Internet Stack**», временно принимает
только Taler/Fediversity (нам не подходят). **Обычные callы возобновятся после лета**
(вероятно осень-2026, под Open Internet Stack). → Прицел подачи — **осень 2026**; до
тех пор делаем M1 (+ начинаем M2) и приходим с более сильной заявкой и прототипом.
Формулировки держим **фонд-агностично** (подходят под Entrust и Commons).

## PET-ось (наш дифференциатор для Entrust)
Три отдельных privacy-вклада — этим заявка и сильна:

1. **Анти-трафик-анализ.** В 1.0 — **size-bucket padding** + унификация обрамления
   медиа-канала: по РАЗМЕРУ нельзя отличить «текст / большое медиа / звонок».
   В спеке ЧЕСТНО: защищаем размер, НЕ тайминг. Полный cover-traffic (скрыть
   «звонит vs молчит») — дорог по батарее (конфликт с power-моделью) → **бэклог/
   research-веха**, не 1.0.
2. **Авто-снятие метаданных** с отправляемых файлов (вкл по умолчанию, можно
   выключить). Надёжно — изображения (EXIF/GPS, ре-энкод); best-effort — документы;
   произвольный неизвестный бинарь — нельзя (честно). **Живёт в пайплайне блобов**
   (scrub-пасс до чанкинга).
3. **Serverless-репутация релеев** (анти-безбилетник) — **способ 1: локальная
   попарная репутация** в SQLite. Узел A даёт расширенный TTL/приоритет хранения
   офлайн-сообщений тем, кто помогал лично A. Sybil-устойчиво (новая личность не
   имеет истории → базовый минимум) и приватно (ничего не светится по сети).
   Способ 2 (крипто-чеки Proof-of-Transit) — **бэклог/research**: красив, но уязвим
   к сговору/Sybil (два ключа штампуют чеки друг другу) и добавляет метадата-лик.

> Терминология: «релей» здесь = **app-level store-and-forward** офлайн-очереди (то,
> что меримо), а не форвардинг самого Yggdrasil (часть протокола, поштучно не мерим).

### Унифицированные блобы (решение 2026-06-27)
Блоб = **один универсальный контент-адресный примитив** (BLAKE3-чанки, pull «дай
блоб X», возобновляемо, лимиты размера/типа — анти-DoS) + тонкий **типизированный
конверт** (mime/тип + метаданные). Через него — аватарки, картинки, файлы,
голосовые, стикеры. Сообщение лишь ссылается на блоб по хэшу. Одна подсистема → ~6
фич почти бесплатно; усиливает заявку («одна подложка для всего медиа»).

## Вехи под заявку (deliverables, формат NGI Zero)
Каждая = осязаемый результат с DoD. Недели — ориентир для бюджета.

- **M1 — Контракт движка + спека** (~4–6 нед). ADR-003 в код: `engine`-крейт,
  Command/Event, JNI-кодек; репатриация стата Сети + офлайн-TTL + презенс. Спека
  протокола. *DoD:* клиент не считает домейн-логику; движок юнит-тестируется без устройства.
- **M2 — Унифицированные блобы + медиа в чате** (~7–9 нед). Крейт `blob` (BLAKE3,
  чанки, pull, лимиты/анти-DoS) + типизированный конверт; потребители — аватарки,
  картинки, файлы; **метадата-scrub** в пайплайне. *DoD:* отправка/приём картинки и
  файла; аватарки сверяются по хэшу; EXIF/GPS снимается.
- **M3 — Офлайн/презенс + репутация** (~3–4 нед). Усиление S6; **локальная попарная
  репутация** (способ 1) → дифференцированный TTL/приоритет. *DoD:* сообщение
  доходит после возврата получателя; помогавшие пиры получают расширенный TTL.
- **M4 — Онбординг, ключ, настройки** (~3–4 нед). Первый запуск, резервная копия
  ключа (сид/файл, FLAG_SECURE), экраны настроек (энергия/медиа/хранилище).
  *DoD:* новый пользователь регистрируется и делает бэкап; настройки не захардкожены.
- **M5 — Анти-трафик-анализ** (~3–5 нед). Size-bucket padding + унификация обрамления
  каналов. *DoD:* размеры на проводе не различают текст/медиа/звонок; спека честно
  описывает границы защиты.
- **M6 — Security-review** (~3–4 нед). `cargo-fuzz` + `proptest` на парсеры
  недоверенных байт; Kani-харнессы на 2–3 парсера; аудит блоб-поверхности.
  *DoD:* парсеры не паникуют ни на каком входе (CI-фаззинг); отчёт аудита.
- **M7 — Релиз-инженерия** (~3–4 нед). Воспроизводимая сборка, F-Droid-метаданные,
  доки (спека, threat model, build/run). *DoD:* воспроизводимый APK; страница
  F-Droid; сборка из исходников по доке.

**Итого ≈ 26–36 недель.**
