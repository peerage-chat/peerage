# План до беты (решение владельца 2026-10-22)

Цель: раздать APK своему кругу (2–5 человек) для ежедневного использования — и не
стыдиться качества и безопасности. Поэтому в бету входит большая часть того, что
раньше числилось «к v1.0»: воспроизводимая сборка, постквантовый обмен ключами,
SEC-3, SEC-4, фаззинг, Kani (по возможности), упоминания, «сохранить лог».

**Дополнено 2026-10-30.** Медиа ADR-014 (LiteRTC) закрыто и проверено на телефоне.

журнал ревью ещё не проходил. Ревью раньше уведомлений (владелец: сначала шлифовать
сделанное, потом строить новое). **Пиры/личи — после беты**, вместе с каналами (H2): без
каналов кэшу блобов и госсипу голов нечего делать, кругу из 2–5 человек стимулы
участия не нужны, а мягкая заморозка позволяет менять протокол осознанно, с версией.

- **0 первым:** после пакетов ревью 3+ на устройстве не запускалось ничего. Регрессии
  из ревью надо поймать ДО того, как поверх ляжет новая криптография, иначе их не
  отличить друг от друга.
- **1 рано:** лог нужен для диагностики всего, что дальше, а не только бета-юзерам.
- **2 до 3:** инфраструктура фаззинга готова к моменту, когда появятся новые
  парсеры рукопожатия, — харнесс пишется вместе с парсером, а не потом.
- **3 одним куском:** PQ поверх статического Box, а затем ратчет — это два слома
  формата и две реализации. Гибридное рукопожатие сразу даёт сессионные ключи, на них
  садится ратчет.
- **4 после 3:** ключ медиа берётся из сессии 1:1 v2 — и в личном звонке, и в
  групповом (комната — полная сетка пар, так что кадр ещё и аутентичен отправителю;
  MLS exporter не понадобился). MLS-256 по замеру отложен: единственный набор с
  Ed25519 — черновой X-Wing, сообщения группы в 7–10 раз больше, Welcome не влезает в
  датаграмму с ~40 участников; PQ группам и так даёт сессия 1:1, по которой идёт весь
  трафик MLS (ADR-013).
- **7 в конце:** до этого меняются зависимости (ML-KEM, фаззинг) — закреплять
  тулчейн раньше значит делать работу дважды.
- **8 после всех ломающих шагов** (3, 4, 5): они и так должны случиться до раздачи.

## Шаг 7 — воспроизводимая сборка (✅ 2026-10-26)

`reproducible/` (Dockerfile + сборка внутри), запуск `scripts/repro-build.sh` из WSL,
`--check` — две чистые сборки и сравнение. Закреплено: базовый образ по digest,
пакеты Debian снимком на дату, Go/rustup/Rust/NDK/cmdline-tools/Gradle — версией и
sha256 (сверены с официальными источниками). Собирается `git clone` коммита,
`SOURCE_DATE_EPOCH` = время коммита, путь постоянный, пути в отладке переписаны;
`libygg` — `-trimpath`, пустой buildid, без `go mod tidy`.

Результат: две независимые сборки `7b5d0ba` в разное время дали побайтно одинаковые
неподписанный APK, `libpeerage_android.so`, `libygg.so`, `libc++_shared.so`. Подробности
и сверка подписанного релиза (`apksigcopier compare`) — `reproducible/README.md`.

Попутно найдено: правка этого шага оборвала перенос строки в `build-ygg-android.sh`, и
Go молча собирал `libygg.so` под хост — поймано линковщиком в контейнере (`7b5d0ba`).

Maven-зависимости проверяются по sha256 (`android/gradle/verification-metadata.xml`,
записи для Windows и Linux; macOS-вариант `aapt2` добавится, когда будет такой
сборщик). Контрольная сборка `023643e` с проверкой хэшей дала те же байты. Не
закреплено, осознанно: `platform-tools` (sdkmanager отдаёт только последнюю, в APK не
попадает). Проверено пока на одной машине; сверка на чужой — при раздаче.

## Шаг 6 — Kani (✅ 2026-10-26)

`scripts/kani.sh [имя]` из WSL (установка один раз: `cargo install --locked
kani-verifier && cargo kani setup`). Доказательства — `mod proofs` под `cfg(kani)`
рядом с кодом, в обычную сборку не попадают. Фаззер проверяет выборку входов, Kani —
**все** входы ограниченного размера:

| Доказательство | Что значит | Время |
|---|---|---|
| `pad::unpad_never_panics` | любой вход до 12 Б: без паники, результат внутри входа | 24 с |
| `pad::pad_round_trips` | `unpad(pad(x, b)) == x`, длина кратна бакету (x ≤ 6 Б, b ≤ 16) | 7 мин |
| `session::no_number_accepted_twice` | окно повторов: номер не принимается дважды, повтор принятого отвергается | 4 мин |
| `session::fresh_number_in_window_is_accepted` | нет ложных отказов: неприходивший номер в окне принимается | 2 мин |
| `mention::accepted_span_is_safe_to_slice` | участок упоминания, прошедший проверку, режет строку без паники | 12 с |

Границы, честно: под Kani окно повторов 128 вместо 2048 (код от размера не зависит,
годится любое кратное 64), последовательности — из двух пакетов (три не уложились в
15 мин); ключи упоминаний и повторная чистка — на тестах и фаззере `mention`.
Находок нет. Кандидаты дальше: заголовок пакета сессии, манифест блоба.

## Шаг 2 — фаззинг (✅ 2026-10-25)

`fuzz/` (отдельный workspace, nightly + cargo-fuzz), запуск `scripts/fuzz.sh [сек]`.
Цели: `wire` (конверт, паддинг, payload + пере-кодирование), `media` (заголовок,
видео-фрагмент, сборщик кадров на потоке), `blob_manifest` (манифест, части из
сети, сборка чанков), `scrub` (JPEG/PNG). Лимит памяти 1 ГБ на вход — телефон.

Первая же минута нашла удалённый краш: часть манифеста с выдуманным `total`
заставляла выделить ~100 ГБ → abort процесса (не ловится `catch_unwind`).
Исправлено, регрессионный тест в `peerage-blob`. Дальше прогон по 2 мин на цель — чисто
(~12 млн входов).

**Не покрыто** (линкуют `libygg` через `messenger`, под санитайзером неудобно):
джиттер-буфер (`media`), конверт группы `AppMsg` (`groupchat`), разбор событий в
`engine`, MLS-обработка (`group`, openmls — их фаззинг на апстриме). Путь — вынести
чистые разборщики из крейтов с транспортом или сделать `peerage-ygg` опциональным.
**Правило:** новый разборщик сетевых байт (рукопожатие шага 3) — сразу со своей целью.

## Шаг 3 — сессия 1:1 v2 (✅ 2026-10-25)

[ADR-012](../adr/ADR-012-dm-session-v2.md), провод — [protocol-spec §2.1](../protocol-spec.md).
`core/src/noise.rs` (Noise XX/XXhfs; классический XX сверен со `snow` байт-в-байт),
`core/src/session.rs` (таблица сессий, `mac1`, окно повторов, смена ключей, очередь до
рукопожатия), мессенджер шифрует только ими; конверт v1 и NaCl Box удалены. Фаззинг —
цель `session`; loopback — весь набор плюс перезапуск получателя посреди сессии.

**Ломает провод:** обе стороны обязаны стоять на новой сборке; хранилище не меняется,
`pm clear` не нужен.

**Осталось:** ProVerif-модель рукопожатия (п. 5 плана проверки ADR-012); живой прогон
на двух телефонах (вместе с шагом 0).

## Шаг 1 — «Сохранить лог»

✅ Сделано 2026-10-25 (`LogExport.kt`). Источник — logcat своего процесса (Rust +
Kotlin) плюс файл падения прошлого запуска (обработчик необработанных исключений).
Очистка на выходе: hex длиннее 16 знаков → первые 6, IPv6-адреса → «[адрес]».
Не ловит: нативное падение (SIGSEGV в Rust/Go) прошлого запуска — его logcat уже
не отдаёт; при надобности — tombstone через `ApplicationExitInfo` (API 30+).

Исходный замысел:

Кольцевой буфер логов в памяти (Rust `log` + Kotlin `Log`) → кнопка в настройках
сохраняет файл через системный «Сохранить как» (SAF). Без контента сообщений,
ключей и сидов; адреса пиров — только укороченными. Без сети: файл человек
пересылает сам.

## Шаг 8 — политика совместимости после раздачи

Мягкая: менять формат в бете можно, но нежелательно и только осознанно.
- Номер версии протокола в рукопожатии и версия схемы БД (`PRAGMA user_version`).
- Смена схемы — миграцией, а не `pm clear`. Если миграция невозможна — явное
  сообщение в приложении, а не молчаливая порча.
- Критичное (безопасность) — ломаем, предупредив бета-юзеров.

**До заморозки — место под другие сети и почтовые ящики** (добавлено 2026-11-19,
[ADR-015](../adr/ADR-015-profile-per-network.md), [ADR-016](../adr/ADR-016-presence-and-mailboxes.md)).
Сами сети (Tor, I2P) и ящики — после беты; в формат до заморозки входит:
- **F1** адрес — из подключа устройства с видом сети в метке; `TK_0 == IK` убрать,
  установки на эпохе 0 при обновлении меняют адрес (объявление контактам, механизм 7g);
- **F2 / E3** подписанная запись адреса v2 (вид, длина, кем подписано, версия) — единый
  формат подписанных записей (адрес, список ящиков, список устройств ADR-010);
- **F3 / E4** адрес переменной длины с видом: в БД, в коде контакта v2 (TLV, слот под
  список ящиков и ключ доступа к onion), в заголовке копии данных;
- **F4** раскладка `files/profiles/<id>/`, `kind` и `hidden` в `profile.json`;
- **F5** правило вывода профиля n из 24 слов (только запись);
- **E1** биты возможностей в рукопожатии рядом с версией протокола;
- **E2** неизвестные поля и TLV не роняют разбор (типы — уже `Unknown`);
- **E5** досылка по своему расписанию, без ожидания «встречи» (поведение, не формат).

Желательно до первого нового адаптера: **R1** единый контракт транспорта (ADR-015 §4),
**R2** свой планировщик на профиль.

## Шаг 7c — отчёты о прочтении и индикатор набора (добавлено 2026-11-01)

Сейчас не отправляются вовсе. До беты — переключатели в «Профиль → Приватность»
(макет `settings/Privacy`), по умолчанию **выключены** (app-ui.md — источник истины).

- **Взаимность** (как в WhatsApp): выключил отчёты — не видишь чужих; то же для набора.
- **Галочки:** две = доставлено, «прочитано» — заливка/цвет второй (решить при реализации,
  `docs/design/ui-redesign.md` → «Мелкие правки»).
- **Канал:** служебные сообщения по `CHAN_CHAT`; набор — эфемерный (не в офлайн-очередь,
  без ретраев, протухает за секунды), с ограничением частоты.
- **M5:** размеры обоих — в существующие бакеты паддинга (threat-model N7); набор ещё и
  раскрывает моменты активности — отметить в threat-model.
- **Группы:** в 1.0 — только 1:1 (решено 2026-11-03): в группе каждая отметка — MLS-сообщение,
  двигающее ратчет у всех N, а набор поверх чувствительного к порядку MLS — риск рассинхрона.
- Движок — ✅ 2026-11-03 (журнал движка, UI 2.10а).

## Шаг 7d — «Поделиться», ярлыки; ссылки — после беты (добавлено 2026-11-01)

- **«Поделиться» из других приложений** (`ACTION_SEND` / `SEND_MULTIPLE`: текст, фото,
  файлы) → выбор чата тем же листом, что и пересылка. Один чат — открыть его с вложением в
  поле ввода; несколько — отправить сразу (решение владельца 2026-11-01).
- **Последние чаты в системном меню** (sharing shortcuts) — за переключателем в
  «Приватности», выключен по умолчанию (решение владельца 2026-11-01): выключенным `ShortcutManager` ничего не
  получает. При выключении — удалить опубликованные ярлыки.
- **Ярлыки на значке**: статические «Добавить контакт», «Мой код»; запуск — через AppLock.
- **Ссылка-приглашение — после беты** (владелец: вариант А, домен `peerage.chat`, берётся
  позже): `https://peerage.chat/add#<код>`, App Links (`assetlinks.json`), статическая
  страница показывает только ключ и ссылку на установку; часть после `#` на сервер не
  уходит. Открытие → «Добавить контакт» → обычный запрос (гейт не обходится). До домена
  тексты не обещают ссылку («QR или код»).

## Шаг 7e — запрос от незнакомца с именем как у контакта (добавлено 2026-11-01)

Личность = ключ, поэтому «ключ контакта сменился» в Peerage не бывает: новый ключ — это
новый человек, и он приходит запросом в контакты. Подмена выглядит так: запрос с тем же
именем и аватаром, что у существующего контакта. В карточке такого запроса — предупреждение
«Имя совпадает с контактом <имя>, ключ другой» и путь «Сверить ключ лично». Сравнение
имён — по нормализованной строке (регистр, похожие буквы кириллицы и латиницы).

✅ 2026-11-17: `peerage_core::lookalike`, поле `lookalike` в запросах; знак у имени в строке
списка, предупреждение в карточке, «Сверить ключ лично» — сканер и шторка сверки. Граница:
совпавшая при такой сверке личность после принятия сверенной не отмечается (отметка — у контакта,
а его до принятия нет); сверка повторяется с экрана контакта.

## Шаг 7f — реакции (добавлено 2026-11-01)

Были отложены на после 1.0 (`docs/v1.0-scope.md`); владелец вернул их в бету — стоят
недорого, потому что путь уже проложен правками и закрепами (`Payload::Edit`, `Payload::Pin`).

- **Payload** `React { id, target, target_mine, emoji, on }` — по образцу `Pin`: ссылка на
  `(отправитель, id)`, `on = false` снимает. Надёжная доставка, `CHAN_CHAT`; в группе — тем же
  MLS-путём, что правка (и `save_group`).
- **Одна реакция на человека**: новая заменяет прежнюю. Состояние — последнее по времени от
  этого отправителя; арбитр не нужен, у каждого своя строка.
- **Проверка на входе**: `emoji` — одна графема, не длиннее разумного предела байт; иначе
  отбросить. Цель должна существовать в этом чате.
- **База**: таблица `reactions(chat, scope, target_sender, target_id, sender, emoji, time)`,
  уникальность по `(chat, scope, target_sender, target_id, sender)`; удаление сообщения
  удаляет его реакции.
- **M5**: размер — в существующий мелкий бакет паддинга; отметить в threat-model, что
  реакция, как и «прочитано», раскрывает момент активности.
- **Уведомления** (решение владельца 2026-11-01): реакция на **своё** сообщение —
  уведомление, **включено по умолчанию**; текст «<имя>: 👍 к «<начало сообщения>»», та же
  строка — в списке чатов. Переключатель «Реакции» в «Уведомления → Прочее». На чужие
  сообщения в группе — не уведомлять.
- Формат ломается → до шага 8.

## Шаг 7g — своё имя и фото в копии данных (добавлено 2026-11-01)

Восстановление по 24 словам возвращает только ключ: своих имени и аватара нет ни в нём, ни
в копии данных (`engine/src/backup.rs`, записи `Manifest` · `Contacts` · `Messages` · `Calls`),
и после переноса на новый телефон человек подписывается заново.

- **Эпоха адреса — время, а не счётчик** (R-118; решение владельца 2026-11-01). Сейчас эпоха —
  счётчик 0, 1, 2… в `transport.json`; его нет ни во фразе, ни в копии, и восстановленный
  телефон поднимается на эпохе 0, а контакты с эпохой N объявление меньшей эпохи отвергают
  (`ContactStore`, монотонность). Новое правило: эпоха 0 — адрес совпадает с ключом (как
  сейчас), иначе эпоха = секунды Unix в момент смены, `max(сейчас, прошлая + 1)` — от сбитых
  назад часов. Восстановленный телефон не знает прошлой эпохи, и знать её не нужно: сразу
  после восстановления он поднимается на эпохе «сейчас» (паузы офлайн не надо — старый адрес
  никто не держит) и рассылает подписанное объявление всем контактам, что знает (из копии
  данных; добавленным заново по коду — при первом обмене, `announce_rotation_to`). «Сейчас»
  заведомо больше любой прошлой эпохи, монотонность у контактов не трогаем. Номер в копию
  класть не нужно.
- Граница: если часы телефона при восстановлении отстают дальше момента прошлой смены
  адреса, объявление отвергнут — показать это в «Сеть» и повторить после синхронизации часов.
- Тест (loopback): сменить адрес → восстановить по фразе на другом движке → контакт
  получает объявление и дозванивается; часы назад → объявление отвергнуто, повтор проходит.
- Новая запись копии `Profile { name, avatar }`; аватар — тем же кадром, что вложения (он
  мал, лимит кадра не грозит). Часть всегда в составе, отдельного переключателя нет: это не
  переписка и не объём.
- При восстановлении — применить, только если своего имени на устройстве ещё нет (не затирать
  то, что человек уже ввёл); дальше обычный `ProfileUpdate` контактам.
- Онбординг (`docs/design/ui-redesign.md` → «Первый запуск»): шаг «Как подписаться» после
  восстановления показывается, только если копии не было или имени в ней не нашлось.
- Тест: экспорт с именем и аватаром → импорт на другой личности → имя и аватар на месте;
  импорт поверх уже введённого имени его не меняет.
- Формат копии ломается → до шага 8.

## Шаг 7h — запуск при включении телефона (добавлено 2026-11-01)

Сейчас в манифесте нет `BOOT_COMPLETED`: после перезагрузки узел не поднимается, пока человек
сам не откроет приложение, — на любом уровне шифрования. Сообщения контактов при этом не
теряются (очередь отправителя у контакта бессрочна, `Tier::outbox_ttl_secs`), но приходят с
задержкой, звонки пропадают.

- Приёмник `BOOT_COMPLETED` (+ `MY_PACKAGE_REPLACED` — после обновления) → `ConnService`, если
  онбординг пройден. `BOOT_COMPLETED` приходит после первой разблокировки, когда файлы
  приложения уже доступны.
- Уровень «Ключ устройства» — узел поднимается сам. «Пароль» / «Ключ и пароль» — узел поднять
  нечем: тихое уведомление «Переписка закрыта паролем · сообщения не принимаются», тап — экран
  пароля (или отпечаток).
- Android 15 запрещает поднимать службу типа `dataSync` из `BOOT_COMPLETED`; у `ConnService`
  тип `specialUse|dataSync` — на этом пути стартовать с `specialUse`.
- На Xiaomi/Huawei без «Автозапуска» система приёмник не вызовет — поэтому строка в разрешениях
  первого запуска («Первый запуск» в `ui-redesign.md`).
- Проверка: эмулятор `adb reboot` → узел в сети без открытия приложения; уровень «Пароль» →
  уведомление, после ввода — досылка накопленного.

## Шаг 7i — приветствие = запрос в контакты (добавлено 2026-11-01)

Сейчас запросом становится первое сообщение чата незнакомцу (гейт, `ContactRequest` в UI-событиях);
человек не знает, что пишет «запрос», и пишет его как обычную реплику. Новое (вид —
`docs/design/ui-redesign.md` → «Контакты и группы»):

- **Payload** `ContactRequest { greeting, name }` — отправляется кнопкой «Отправить запрос» на
  экране добавления, надёжно, `CHAN_CHAT`. `greeting` — до разумного предела (≈ 500 символов),
  может быть пустым; `name` — самоназвание (фото — только после принятия, как профиль контактам).
- **Получатель**: карточка запроса — имя, приветствие, начало ключа, предупреждение шага 7e при
  совпадении имени с контактом. Принять → контакт, приветствие — первым сообщением чата, назад
  уходит `ContactAccept`. Отклонить — молча, без ответа (не раскрывать, что человек читал).
- **Отправитель**: пока нет `ContactAccept`, остальные сообщения этому контакту не уходят, а
  ждут в своей очереди со статусом «ждёт принятия» (не тратят чужой бюджет незнакомцев и не
  теряются у получателя). `ContactAccept` → очередь выпускается.
- **Взаимное добавление**: если получатель уже держит отправителя в контактах — запрос
  принимается сам, приветствие ложится в чат, `ContactAccept` уходит сразу.
- Старое правило «первое сообщение незнакомцу = запрос» убирается.
- **M5**: оба payload — в бакет текста; бюджет незнакомца на приём (`Tier::Stranger`) не меняется.
- Тест (loopback): запрос → принятие → удержанные сообщения доставлены по порядку; взаимное
  добавление; отклонение — отправитель остаётся в «ждёт принятия», получатель ничего не шлёт.
- Формат ломается → до шага 8.
- ✅ 2026-11-17: движок и экран «Добавить контакт» (UI 4.1); журнал движка; живой прогон на двух
  эмуляторах — запрос, удержание, принятие, ошибки кода.

## Шаг 7j — передача прав админа; название и фото группы (добавлено 2026-11-01)

Админ в группе один — создатель (`GroupManager::admin_keys`); только он удаляет и закрепляет. Если
он выходит, группа остаётся без админа: удалять некому, а выход участников становится только
локальным (`on_leave_request` отзывает лишь админ).

- **Передача прав**: прикладное MLS-сообщение админа `AdminTransfer { new_admin }` (автор
  аутентифицирован MLS; принимается только от текущего `admin_key`, с `save_group`). Новый
  админ — только текущий участник. Из шторки участника и обязательным выбором при выходе админа
  («Передать … и выйти» / «Выйти без передачи»).
- **Название**: админ меняет — `send_name` уже рассылает имя; проверить, что имя принимается
  только от админа, иначе любой участник переименует группу всем.
- **Фото группы**: блоб-аватар по образцу аватара контакта (миниатюра — отдельным блобом, M5),
  ставит только админ.
- Тест (loopback): передача → новый админ удаляет участника, старый уже не может; выход с
  передачей; чужая попытка `AdminTransfer` отвергнута.
- Формат ломается → до шага 8.

## Шаг 7k — копия данных ключом из 24 слов (добавлено 2026-11-01)

Сейчас копия (`peerage_core::backup`) закрыта только отдельным паролем: ключ устройства в ней
не годится (живёт в одном телефоне), а ключ из 24 слов не рассматривался. Решение владельца:

- **По умолчанию** — ключ копии из 24 слов: `Identity::derive_subkey("peerage:backup:v1")`
  (своя метка; ключ подписи не используется). Помнить нечего; на новом телефоне — «24 слова →
  файл → готово», шаг с паролем уходит.
- **«Дополнительно закрыть паролем»** — по желанию (копии в облаке): ключ = KDF(пароль) смешан
  с ключом из слов, нужны оба. Без пароля такую копию не откроют и 24 слова.
- Следствие: копию открывает только та же личность. Копию, снятую до «Начать заново» (новая
  личность), новая личность не откроет — сказать на экране «Начать заново».
- В заголовке файла — флаг «есть пароль», чтобы восстановление спрашивало пароль только тогда.
- Цена — утечка 24 слов открывает и старые копии без пароля; кто их хранит в облаке, ставит
  пароль (подпись к переключателю).
- Тест: экспорт без пароля → импорт на той же личности после восстановления по фразе;
  чужая личность — отказ; с паролем — без пароля отказ, с паролем ок.
- Формат копии ломается → до шага 8.
