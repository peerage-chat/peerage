# План 2 — укрепление до абсолюта

База уже сильная: пройден аудит (`SECURITY.md`: H1–L4, DEP1–3 закрыты), есть
верификация ключей (8 BIP39-слов out-of-band, флаг `verified`), at-rest
(`vault.rs`, XChaCha20-Poly1305), MLS-группы, ratchet ironwood (FS/PCS/anti-replay),
фильтрация медиа по источнику, dedup, cargo-deny. Этот план — **за пределы базы**.

## Честная рамка (threat model)

«Абсолют» недостижим: взломанная ОС эндпоинта = всё насмарку (читают экран, ключи
из памяти, кейлоггер) — это вне власти приложения. Реальная цель:

> Сделать протокол + приложение + реализацию настолько прочными, что **единственная
> жизнеспособная атака — таргетированная компрометация эндпоинта** (дорогая,
> заметная, по одной цели), а массовая слежка и сетевые атаки — экономически
> невозможны. И даже стоимость эндпоинт-атаки поднять.

Содержимое (при чистом эндпоинте и сверенных ключах) уже защищено сильно. Фронтир —
**метаданные** и **глубина гарантий реализации**.

## Фазы (по влиянию)

### S1 — Закрыть известную остаточную поверхность (из SECURITY.md «новая поверхность»)
- **Подписать СОДЕРЖИМОЕ presence-маячка** (flags, gid), а не полагаться только на
  конверт NaCl Box → закрывает подмену маячка MITM'ом внутри группы.
- **Rate-limit входящих маячков** per source/gid (DoS через частые маячки).
- **Авторизация входа в комнату** (одобрение админом — см. модель каналов).
- **H6: полный повторный аудит** новых подсистем (комнаты, JNI-мост, MediaCodec-путь).

### S2 — Гарантии реализации (лестница верификации — уже в ROADMAP)
Самый вероятный практический эксплойт — баг в парсере недоверенных байт.
- **Фаззинг (cargo-fuzz)** ВСЕХ парсеров недоверенного входа: presence-маячок,
  медиа-фрагменты (вкл. новый байт ориентации), group blob, MLS-сообщения. РАНО.
- **Kani** на самые критичные парсеры.
- `unsafe` держать минимальным (уже сосредоточен в transport, L3) + **MIRI** на него.
- Supply chain: cargo-deny (есть) + **cargo-vet**, пиннинг, минимум зависимостей.
- **TLA+** на протокольную логику (порядок/ADR-002, presence, офлайн-очередь) — post-1.0.

### S3 — Глубина at-rest
- **DEK + сменная обёртка ключа** (выбираемый уровень: Keystore / Argon2id-passphrase
  / оба) поверх существующего vault — пользователь сам выбирает «привязка к
  устройству» vs «парольная защита» vs «оба».
- **Зануление** в Rust-ядре (`zeroize`) ключей и расшифрованного контента.
- **`FLAG_SECURE`** на окно (запрет скриншотов/записи, нет превью в «недавних»);
  плейнтекст не в логи; отключить обучение клавиатуры на поле ввода; чистка буфера обмена.
- Метаданные at-rest (граф контактов/индексы) — проверить, что под vault; минимизировать.

### S4 — Сопротивление метаданным (СДВИНУТЬ границу модели — главный фронтир)
Сейчас явно вне модели (маршрутная метадата Yggdrasil). Здесь двигаем границу.
- **Развязка IP↔ключ:** прямой пир сейчас узнаёт твой IP. Многохоповая/onion-
  маршрутизация внутри меша или паддинг, чтобы IP не линковался с ключом.
- **Sealed-sender:** скрыть отправителя от промежуточных relay (личность узнаёт
  только получатель).
- **Анти-трафик-анализ (opt-in «параноик-режим»):** бакетизация/паддинг размеров,
  cover-traffic постоянной скорости, развязка времени отправки от набора текста.
- **Минимизация presence:** маячки вещают «онлайн + в звонке» — сделать opt-in/scoped.
- Честно: полная защита от глобального пассивного наблюдателя — research-grade
  (миксеты). Цель — **резко поднять стоимость**, opt-in для самых параноидальных.

### S5 — Глубина целостности групп/протокола
- **Ghost-user / прозрачность ростера:** сверх H1 (проверка KeyPackage) — изменения
  состава видимы и проверяемы ВСЕМИ участниками (transparency-log / подписанные
  упорядоченные membership-операции; завязка на ADR-002).
- **Паритет шифрования медиа:** убедиться, что A/V-ключи имеют те же FS/PCS, что и
  сообщения (не статичный ключ) — и задокументировать.
- **Anti-replay** — airtight, под TLA+.

### S6 — Злоупотребления / доступность
- **Только контакты по умолчанию**; proof-of-work / rate-limit для незапрошенного
  контакта; per-peer лимит входящих.
- **Анти-цензура:** детект выборочного дропа relay'ем (acks/избыточность/альт-пути).

### S7 — Экосистема доверия
- **Воспроизводимые сборки** — проверяемо, что APK = исходники (критично для
  мессенджера «доверяй бинарю»).
- **Внешний аудит + bug bounty** (post-1.0).
- **Честный security-UX:** не продавать «невзламываемо»; ясно «что защищено, что нет».

## Порядок
S1 (закрыть известное) и S2 (фаззинг — дёшево, рано) — первыми: бьют самые
вероятные реальные атаки. S3 (at-rest) — следом. **S4 (метаданные) — стратегически
главное и самое трудное, марафон.** S5/S6/S7 — сквозняком.

## Принцип
Каждый шаг — defense-in-depth: не «стена», а удорожание атаки. Самый честный
вклад — заставить противника атаковать ОС за миллион на каждую цель отдельно,
вместо дешёвого массового сбора. Это уже меняет баланс против слежки.
