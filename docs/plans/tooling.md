# Инструменты разработки: что улучшить (решение владельца 2026-10-31)

Зачем: больше всего времени уходит не на код, а на обвязку вокруг него — вызовы WSL,
долгие прогоны мутантов, ручную сборку, ручное закрытие находок ревью. Список
составлен по трениям, замеченным при работе над ревью медиа (R-109…R-117). Владелец:
«я за все».

| # | Что | Почему | Статус |
|---|---|---|---|
| 1 | **`scripts/w` — одна точка входа в WSL.** `scripts/w cargo test -p litertc` из Git Bash: аргументы уходят в WSL как есть (`wsl --exec`), окружение (`local.env`, cargo/go в PATH, `LD_LIBRARY_PATH` до libygg) собирается внутри; `--cd <каталог>` — другой каталог. | `wsl bash -c '…'` ломался на кавычках: Git Bash подставлял `$PATH` и пути, heredoc-и доходили битыми, фоновый `&` умирал вместе с wsl. | ✅ |
| 2 | **Мутанты по изменённому.** `mutants.sh --since <коммит>` (cargo-mutants `--in-diff`) и файл принятых равносильных мутантов, которые скрипт отфильтровывает. | Полный прогон четырёх файлов — 25 мин, а проверять нужно тронутые строки; одни и те же равносильные (границы f64 и т. п.) приходилось разбирать заново. | |
| 3 | **`crap.sh` считает и интеграционные тесты** (`--lib --tests` по умолчанию). | С `--lib` движок показывал 0 % покрытия у кода, который на деле гоняют `engine/tests/*`. | |
| 4 | **Одна команда сборки APK** (`.so` → libygg → gradle → подпись), без adb; та же последовательность — в README («Сборка»). | Сборка — цепочка шагов, порядок важен (`.so` до APK). Ставит владелец сам: копирует APK на телефон; беспроводная отладка включается редко, adb — только для логов, отдельно. | |
| 5 | **Тесты messenger/engine без WSL**: `impl Transport for Node` перенести из messenger в engine, чтобы messenger и его тесты не линковали libygg. | Тесты пойдут на Windows-хосте — быстрее и без пункта 1. Архитектурная правка: убирает причину, а не обходит её. | |
| 6 | **Журнал ub-mode в файл по ходу работы** (`.claude/ub-log.md`: строка после каждого коммита — что и зачем). | Контекст сжимается посреди задачи; лог действий для отчёта восстанавливался по пересказу. | |
| 7 | **Скилл «закрыть находку ревью»**: строка сводки REVIEW.md → «исправлено (хэш)», раздел «Исправлено…», запись в «Журнале полировки» BUGS.md, следующий номер — в памяти. | Делается руками каждый раз, легко что-то забыть. | |

Не делаем: внешние плагины и коннекторы; хуки, форматирующие на каждое сохранение
(правило проекта — `cargo fmt` только для litertc и engine, хук бы его нарушил).
