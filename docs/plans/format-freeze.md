# Шаг 8 — заморозка формата: план реализации

Источник решений — [ADR-015](../adr/ADR-015-profile-per-network.md) (F1–F5, R1–R2) и
[ADR-016](../adr/ADR-016-presence-and-mailboxes.md) (E1–E5); политика после заморозки —
`beta.md` → «Шаг 8». Этот файл — только порядок и единицы работы: что за чем, чем проверить.
Составлен 2026-11-23.

Правило на весь шаг: до раздачи беты формат ломать можно, но **эмуляторы и телефон юзера не
чистим** (`pm clear` нельзя) — каждое изменение формата идёт с переходом со старого состояния
при запуске. Каждая единица — отдельный коммит движка с записью в журнале движка.

## Порядок

Сначала то, на что опирается остальное: формат подписанной записи, потом адрес на нём, потом
код обмена и копия, где адрес едет. Раскладка профилей (F4) — последней: она трогает
хранилище клиента, а не протокол.

### 8.1 Подписанная запись v2 (F2 / E3) — `core` — ✅ 6a8ce85

- Один формат для адреса, списка ящиков и списка устройств:
  `"peerage:rec:v2" ‖ type(1) ‖ signer(1) ‖ len(2) ‖ body`, подпись ed25519 по этим байтам.
  `type`: 1 — адрес, 2 — ящики (ADR-016), 3 — устройства (ADR-010); `signer`: 0 — личность.
- Тело записи адреса: `kind(1) ‖ epoch(4) ‖ len(2) ‖ addr`. `kind`: 1 — Yggdrasil.
- Разбор строгий: длины сходятся, неизвестный `type` / `signer` — отказ при проверке, а не
  паника. Под фаззинг (`scripts/fuzz.sh`) — новая цель.
- Убрать `rotate_msg` / `sign_transport_rotate` (v1) — объявление смены адреса несёт запись v2.
- **Тесты:** запись одного вида не проверяется как запись другого; адрес для `kind` A не
  проверяется для `kind` B; порча любого байта — отказ.

### 8.2 Адрес из подключа с видом сети (F1) — `core`, `engine` — ✅ 18c8152

- `transport_seed(kind, epoch) = derive_subkey("peerage:transport:v2/{kind}/{epoch}")` для всех
  эпох; `TK_0 == IK` и вывод v1 убраны — двух форматов до заморозки не держим.
- При запуске адрес, выданный не по текущему выводу (`transport.json` без `v = 2`), или новая
  установка → эпоха «сейчас» и объявление всем контактам (механизм 7g).
- Обновились оба, не услышав друг друга, — связь возвращает код: код известного контакта
  (сверка или «добавить») применяет подписанный адрес, если эпоха новее; хватает скана с
  одной стороны (проверено на эмуляторах).

### 8.2b Отказ по эпохе (R-120) — ✅ ecb484b

- Объявление с эпохой ≤ известной — не молча: ответ-отказ, в котором контакт возвращает
  **нашу же подписанную запись** с известной ему эпохой (доказательство — иначе любой контакт
  мог бы сдвинуть нашу эпоху к пределу). Отправитель проверяет свою подпись, поднимает эпоху
  выше и объявляет снова. Стору контакта — хранить подпись записи (колонка).
- **Тесты:** восстановление с часами позади прошлой смены — контакт в итоге принимает адрес;
  отказ без верной подписи игнорируется.

### 8.3 Адрес с видом и длиной (F3) — `core`, `engine` — ✅ 33ff1ff

- Адрес контакта — только его подписанная запись (`transport_rec` / `transport_sig`): вид сети,
  длина, эпоха — в ней; hex-колонки удалены. В мессенджере `PeerKey = [u8; 32]` остаётся внутри
  адаптера Yggdrasil до R1 (там же — попытка по ключу личности, пока адреса нет).
- Копия данных: `kind` в манифесте (другой вид — `Foreign`); адрес контакта едет его записью.

### 8.4 Код обмена v2 (F3 / E4 / E2) — `core`, `engine`, клиент — ✅ 09de1a9

- `PEERAGE:` + base32 (без паддинга) от версии, вида сети и TLV: личность, запись адреса v2,
  её подпись, имя; номера слота ящиков (5) и сетевых добавок (6) заняты. Base32 в верхнем
  регистре вместе с префиксом — алфавитно-цифровой режим QR (плотнее байтового).
- Код другого вида — явная ошибка (`"foreign"`), новой версии — `"newer"`; неизвестный TLV
  пропускается (E2). Старый код не читается — двух форматов до заморозки не держим.
- **Тесты:** неизвестный TLV не роняет разбор; чужой вид — отказ; порча подписи — отказ.

### 8.5 Версия протокола и биты возможностей (E1) — `core::session`, `core::db`, `messenger` — ✅ ХЭШ

- В подписанной части рукопожатия 1:1 (ADR-012) — `hello`: старшая и младшая версии и
  битовое поле возможностей (бит 0 — «ящик»). Общей версии нет — понятный отказ с обеих
  сторон (`Received::Incompatible`), не порча сессии; инициатор не стучится 10 мин.
  Показ отказа в UI — пока только лог: старой стороне он понадобится, лишь когда новая
  версия перестанет говорить версию 1 (`protocol-spec.md` → hello).
- `PRAGMA user_version` у базы: схема заморозки — 1, дальше — шаги по номеру; база новее
  сборки — явная ошибка.

### 8.6 Доставка не ждёт встречи (E5) — `engine` / `messenger`

- Досылка из офлайн-очереди — по своему расписанию, а не только по приходу пира. Новых
  пакетов в сеть не добавлять: двигается только код. Поведение проверяет существующий
  `engine/tests` офлайн-досылки.

### 8.7 Раскладка профилей (F4) и правило профиля n (F5)

- `files/profiles/<slot>/`: всё, что называет профиль (`profile.json` с `kind`, `hidden`,
  база, блобы, хранилище) — внутри; имя слота непрозрачно; общего списка нет. Главный профиль
  сейчас — единственный; перенос текущих файлов в слот — при запуске, атомарно.
- **Открытый вопрос владельцу:** чем открывается слот главного профиля без пароля (сейчас
  Keystore / биометрия) — секрет слота в Keystore.
- F5 — только правило в ADR-015 (`peerage:profile:v1/{n}`) и тест, что профиль 0 = текущий seed.
