# План доведения до 1.0 — порядок исполнения (продукт-полиш → вехи)

**Статус:** рабочий план, 2026-06-28. Дополняет [v1.0-scope.md](v1.0-scope.md) (вехи
M1–M7 НЕ меняются), задаёт ПОРЯДОК для прототипа под заявку: сначала довести
calls/chats/groups до «законченного» вида (сильное демо), потом backend/PET-вехи.
Подача — осень 2026 (~2 мес, успеваем).

Развязка, которую важно держать: **«доделать чаты/группы» = дешёвый UX-полиш
(сейчас) + медиа/вложения (это M2 — крейт `blob`)**. Медиа делаем один раз в M2 для
чатов И групп разом; не размазываем блобы по ad-hoc коду.

## P0 — Звонки: добить экраны
Главный экран-сетка готов; вспомогательное — нет. Аудит кода vs
[call-ui.md](design/call-ui.md):

**Готово:** сетка (раскладка 1/2 стопкой, 3+ по 2, последний на ширину), видео
cover-crop, своё превью с голубой рамкой, имя+mic-off оверлей, тап→chrome, нижняя
панель (Пригласить·Микрофон·Видео·Выход) со статусом mic/video, мгновенный выход
(PRESENCE_LEFT), базовое «Вы одни» и базовое входящее (Принять/Отклонить).

**Не готово / частично (→ сделать):**
1. Кнопка **«Настройки»** (право-верх) → **экран настроек звонка** (вывод звука,
   разрешение, энергорежим) — сейчас заглушка `{}`.
2. **Экран шаринга видео** (долгий тап «Видео»): источник Камера/Экран, фронт/тыл,
   живое превью, разрешение/fps ТОЛЬКО доступные на устройстве, битрейт (авто+правка),
   «Показать». Строки `share_*` уже есть, экрана нет.
3. **Экран настроек аудио** (долгий тап «Микрофон»): битрейт, устройство ввода/вывода.
4. Кнопка **«Пригласить»** в звонке — заглушка `{}`.
5. **Входящее приглашение** — добить до спеки: пресет mic/video перед входом, строка
   «кто уже в комнате» (Боря и ещё N), ожидаемый суммарный трафик «~M МБ/мин».
6. **Чип суммарного входящего трафика** (лево-верх главного экрана + в фуллскрине).
7. **Даблтап тайла → фуллскрин участника** (видео cover, имя+трафик слева-сверху,
   «свернуть» справа) — в DM-звонке нет.
8. **Авто-скрытие chrome** по таймеру.
9. **«Вы одни»** — своё превью при камере-вкл (сейчас всегда аватар).
10. **Active-speaker** зелёная рамка (+ позже свап декодеров/гистерезис/пиннинг при >5).
11. **Тех-инфо оверлей** (пинг/разрешение/fps/битрейт на участнике; тумблер в общих
    настройках).

Порядок внутри P0: настройки-звонка + шаринг-видео (4 п.1-3) → пригласить/входящее
(4-5) → трафик/фуллскрин/автоскрытие (6-8) → «вы одни»/active-speaker/тех-инфо (9-11).

## P1 — Личные чаты: UX-полиш (без медиа)
Текст-чат рабочий. Дешёвые улучшения: контекст-меню сообщения (копировать/удалить/
reply), длинный тап, детали статуса доставки, мелочи скролла/пустых состояний.
(Вложения/картинки/голосовые — НЕ здесь, это M2.)

## P2 — Группы: UX-полиш + инвайты-как-сообщения
- **Инвайты как «личные сообщения-приглашения»** (Discord-style «приглашение на
  сервер»): вместо тихого key-request/reply — приглашение приходит ОТДЕЛЬНЫМ сообщением
  в личку, получатель видит карточку и жмёт «Вступить». Решение владельца 2026-06-28.
- ✅ **Надёжный invite-хендшейк** (2026-07-02) — `group_key_request/reply` переведены на
  `send_reliable` (retry-until-Ack), Welcome уже был надёжен. Закрыта «последняя дыра
  доставки»: инвайт больше не теряется на холодной сессии. Покрыто loopback-тестами
  (`engine/tests/group_flow.rs`: invite/kick/leave, в т.ч. под потерями пакетов).
- **Имя группы передавать** при вступлении (сейчас joiner получает дефолт — см.
  [[group-message-reliability]]).
- Админка группы: список участников, удалить/добавить, выход из группы.
- Подчистить осиротевший `Screen.Groups` (dead-code).

## P3 = M2 — Унифицированные блобы + медиа в чате
Крейт `blob` (BLAKE3, чанки, pull, анти-DoS) + конверт; картинки/файлы/голосовые/
аватарки — закрывает медиа-часть P1 И P2 разом. + metadata-scrub (EXIF). См. scope M2.

**Прогресс 2026-07-02:**
- ✅ Крейт `p2p-blob`: контент-адресный примитив (build/Reassembler/Manifest/Limits),
  по-чанковая + итоговая BLAKE3-проверка, анти-DoS. `cargo test -p p2p-blob` (хост).
- ✅ `blob::scrub`: снятие EXIF/GPS с JPEG/PNG без ре-энкода (PET-ось).
- ⏳ Осталось: сетевая докачка (pull-протокол по мешу: запрос манифеста/чанков +
  Event/Payload + blob-store в движке) — тестируется loopback-харнесом; интеграция в
  чат (отправка/приём картинки, аватарки по хэшу) — Android UI, нужен девайс.

## P4+ — Backend/PET-вехи (как в scope)
M3 (офлайн-outbox + бюджет ресурсов) → M5 (анти-трафик-анализ) → M6 (security/fuzz) →
M7 (релиз/F-Droid/threat-model). M4 (онбординг/ключ/настройки/SAS) — встроить по ходу
(часть настроек уже трогаем в P0/P2).

---

**Логика:** P0–P2 = видимая завершённость продукта (демо). P3 (M2) = медиа-подсистема,
честно одна на чаты+группы. P4+ = PET-дифференциаторы заявки.
