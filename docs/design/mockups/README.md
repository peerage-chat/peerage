# Макеты экранов (HTML)

**Визуальный источник истины** по внешнему виду экранов. Дополняет
[`app-ui.md`](../app-ui.md): там — *почему/поведение/навигация*, здесь — *как выглядит*
(точные цвета, отступы, иерархия). Реализация в Compose идёт **1-в-1 по макету**
(правило CLAUDE.md), а не по текстовому описанию.

## Почему HTML, а не картинки

- Точные значения (hex/px/отступы) — это буквально CSS, а не «на глаз с пикселей».
- Diff-абельно, живёт в репо, переживает смену модели с точными числами.
- Сам себе референс токенов: цвета/отступы берутся из [`tokens.css`](tokens.css),
  который **зеркалит** `android/.../Tokens.kt`.

Оговорка: HTML-раскладка ≠ Compose механически (flexbox vs Column/Row). Макет — это
**визуальный контракт** (вид, отступы, иерархия, цвет, иконки), а не код для транспиляции.

## Конвенции

- Один экран = один `*.html`, standalone (открывается в браузере как есть).
- Цвета/отступы/радиусы — **только** через `var(--…)` из `tokens.css`. Инлайн-hex —
  лишь для одноразовых демо-данных (цвет конкретной аватарки).
- Иконки — **Tabler** (`ti ti-<name>`, обводка), как в приложении (`ui/TablerIcons.kt`).
- Телефонная рамка ~390px (Compact). Адаптив (Medium/Expanded) — см.
  [ADR-005](../../adr/ADR-005-ui-adaptivity-platforms.md), отдельными макетами при надобности.
- Правишь `Tokens.kt` → синхронизируй `tokens.css` (и наоборот).
