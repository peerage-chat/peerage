# План доведения UI до финального уровня (перед M6)

Рабочий документ этапа между M5 и M6. Отвечает на один вопрос: **что именно должно
быть сделано, чтобы UI считался законченным** — чтобы полировка имела конец, а не шла
по ощущению «ещё бы вот тут подправить».

Источник истины по внешнему виду — [`app-ui.md`](app-ui.md) и HTML-макеты в
[`mockups/`](mockups/); этот файл — только про объём работ и порядок.

## Критерий готовности

UI считается финальным, когда одновременно:

1. **Нет заглушек на видимых путях.** Ни одной кнопки/строки, которая нарисована, но
   ничего не делает. Либо работает, либо её нет на экране.
2. **Каждый экран имеет макет**, и Compose совпадает с ним 1-в-1 (правило проекта).
3. **Скриншот каждого экрана снят на эмуляторе** и приложен к соответствующему коммиту
   — приёмка глазами, а не «по описанию похоже».
4. Новый код — на `Tokens.*`, без инлайн-хекса и магических dp.

Вне критерия (осознанно): адаптивность под планшет/ландшафт и всё, что относится к
экрану звонка (см. «Вне скоупа»).

## Инвентарь: что есть против того, что спроектировано

Ниже — фактическое состояние кода на момент составления плана, а не пожелания.

### Готово и переделки не требует
- Главная: рейл папок, квадратные аватары с presence, индикатор пиров, поиск, FAB.
- Групповой чат: баннер активной комнаты (`GroupScreens.kt:217`), имена отправителей
  цветом, аватарки на входящих, системные строки.
- Сеть: статус, метрики, «Мой узел», режим участия, список пиров.
- Онбординг: все четыре шага, включая экран сид-фразы под `FLAG_SECURE`.
- Контакты, глобальный поиск, гейт запросов, инвайт-карточки групп.
- Чат: чип даты, E2E-баннер, карточка невыкачанного вложения, статусы доставки.

### Э1. Чат: блоки сообщений и вложения — СДЕЛАНО
| Что | Состояние |
|---|---|
| Группировка подряд идущих сообщений | ✅ общая логика в `Components.kt` (окно 5 мин, отступ 2/8dp, шов 5dp), DM и группы |
| Лист вложений | ✅ `AttachSheet.kt`: сетка галереи 3×, мультивыбор с номерами, чип размера, камера, файл, аудио |
| Камера как источник | ✅ обычная плитка (снимок через `TakePicture`); живой предпросмотр отложен (см. «Задел на будущее») |
| Мультивыбор | ✅ порядок выбора виден номерами, счётчик на кнопке отправки |
| Эмодзи-панель | ✅ `EmojiPanel.kt`: недавние, 7 категорий, забой по графемам |
| Подпись к вложению | ⚠️ **частично.** Поля для текста в `Payload::Media` нет, поэтому подпись уходит ОТДЕЛЬНЫМ сообщением следом за вложениями. Выглядит близко (соседние пузыри одного блока), но это не подпись. См. «Требует движка» |
| Ответ на сообщение / пересылка | нет (в `app-ui.md` не описаны — решить, входят ли в v1.0) |

Ограничение, всплывающее вместе с пикером: `sendUriAttachment` (`ChatScreen.kt:195`)
читает файл целиком в память (`readBytes()`). Для картинки это нормально, для видео на
несколько ГБ — нет. Отправка потоком — работа по движку, не по UI; см. «Требует движка».

### Э2. Видимые заглушки — СДЕЛАНО
| Что | Состояние |
|---|---|
| `+` в рейле папок | ✅ ведёт в управление папками |
| Редактор папок | ✅ `FolderScreens.kt`: список + редактор (имя, значок, типы, конкретные чаты, исключения, живой счётчик, удаление с пояснением) |
| Тап по индикатору пиров | ✅ ведёт в «Сеть» |
| Карточка «Офлайн-очередь» | ✅ ведёт на `OutboxScreen.kt`: разбивка по получателям, причина задержки, очистка по одному через долгий тап и «всё» в два шага с удержанием |
| Экран «Хранилище» | ✅ переписан по макету: состав по типам, разбивка по чатам, очистка, блок резервной копии данных |

Пользовательские папки живут в prefs на клиенте, а не в движке: папка — это ВИД,
к протоколу отношения не имеет, собеседник о ней ничего не знает. В движок добавлены
только те данные, которых там не было: разбивка очереди по получателям
(`outbox_by_peer_json`, `clear_outbox_all`) и хранилища по типам/чатам.

### Э3. Визуальный fingerprint — СДЕЛАНО
Знак = форма (16) × цвет (16) = 8 бит; 12 знаков сеткой 6×2 = 96 бит. Рисует само
приложение на Canvas (`ui/Fingerprint.kt`) — байт-в-байт одинаково на любом устройстве,
без зависимости от шрифта. Деривация в ядре (`visual_fingerprint`, домен-сепаратор с
версией) — одна реализация на все клиенты; тесты на детерминированность и на то, что
это не «просто SHA-256 ключа». Показывается в профиле контакта и на «Мой ключ», слова
BIP39 оставлены рядом.

**Расхождение с исходной формулировкой:** в `app-ui.md` было «эмодзи из своего SVG-
набора». Рисовать 256 осмысленных пиктограмм — отдельный художественный проект, а
причина выбора («не зависеть от шрифта устройства») выполняется и геометрией. Текст
спеки приведён к реализации.

## Порядок

**Э0. Макеты — согласованы** (правки внесены). Добавлены `chat-blocks.html`,
`attach-sheet.html`, `contact-profile.html`, `folder-editor.html`, `calls.html`,
`storage.html`, `outbox.html`. Блоки вынесены отдельным макетом, потому что `chat.html`
чередует стороны и правила склейки в нём не заданы.

Решения, принятые на согласовании (расходятся с первой версией макетов):

- **Время и галочки — на каждом сообщении**, не только на последнем в блоке. Блок
  держат отступ, скругление шва, одно имя сверху и один аватар снизу.
- **Пикер вложений — вертикальная сетка 3 колонки** со скроллом вниз, а не
  горизонтальная лента.
- **Строка ввода не исчезает; лист выдвигается из неё.** Подпись пишется в обычном поле
  сообщения — отдельного «поля подписи» нет.
- **Адрес контакта показывается целиком**, без сокращения многоточием: его сверяют и
  диктуют.
- **Очистка очереди: долгий тап → меню → подтверждение**; плюс «Очистить всё» в два
  шага, где второй требует удержания.
- **Чип размера — на каждом превью** в пикере, крупные подсвечены янтарным.
- **Кнопки «Вся галерея» нет:** сетка прокручивает всю плёнку, остальное — через «Файл».
  Лишняя мишень рядом с необратимой отправкой не нужна.
- **«Вся галерея» — в шапке листа**, а не рядом с кнопкой отправки: мелкая ссылка в
  двух десятках пикселей от необратимого действия ловила промахи.
- **Время в пузыре — абсолютно в правом-нижнем углу + инлайн-распорка** под него
  (34px входящие, 52px свои). Текст остаётся по центру рамки, время сидит ниже его
  базовой линии. Ни отдельная строка, ни обтекание не подходят. Правило приведено к
  этому и в `chat.html`; у пузырей с реакциями/медиа время остаётся обычной строкой.

Открытых вопросов по макетам нет.

Дальше — по независимости, каждый этап заканчивается скриншотами:

**Э1 → Э2 → Э3 → Э4 → Э5.**

Чат первым, потому что это главный экран и там же самая заметная нехватка. Заглушки
вторыми — они дешёвые и каждая читается как «недоделано». Fingerprint третьим: работа
изолированная (свой набор + маппинг + два места показа), но требует аккуратности —
маппинг версионируется, смена набора инвалидирует прошлые сверки. Экраны последними:
самый большой объём вёрстки и часть из них ждёт движок.

**Э5. Анимации.** Сейчас всё появляется мгновенно: панели, листы, сообщения, экраны.
Нужны короткие переходы — выезд листа вложений и панели эмодзи снизу, появление нового
пузыря, смена экранов, раскрытие карточки вложения в пузырь после докачки. Держать
скромно (150–250 мс, без пружин и отскоков): это мессенджер, а не витрина. Делать
последним — анимировать имеет смысл то, что уже не будет переставляться.

## Требует движка, а не только вёрстки

Честно вынесено отдельно, чтобы не выяснилось в процессе:

- **История звонков** — журнала в движке нет. Нужны хранение записей (кто, направление,
  длительность, комната) и выдача в UI.
- **Сохранённое** («заметки себе») — нет ни хранилища, ни маршрута.
- **Отправка вложения потоком** — чтобы пикер не упирался в размер файла. Приёмная
  сторона потоковая уже сейчас (`blob/src/disk.rs`), отправляющая — нет.
- **Подпись к вложению** — в `Payload::Media` поля для текста нет.

## Задел на будущее (не в v1.0)

- **Живой предпросмотр камеры** в плитке пикера вместо иконки, возможно с плиткой на
  два столбца (как в Telegram). Требует Camera2-превью внутри листа.

## Вне скоупа этого этапа

- **Адаптивность** (`WindowSizeClass`, ADR-005) — структурный проход по всем экранам,
  а не полировка; после v1.0 либо отдельной вехой.
- **Экран звонка** — эталон там макеты юзера (`call-ui.md`), и известные дефекты
  (растянутое своё превью, повёрнутое удалённое видео) лежат в медиа-пайплайне, а не
  в вёрстке. Чинить отдельно.
- Ответы/пересылки/реакции — не описаны в `app-ui.md`; если нужны в v1.0, сначала
  дизайн-решение.
