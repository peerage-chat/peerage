# Дизайн UI звонков (утверждённое)

Спецификация ВИДА и ПОВЕДЕНИЯ экранов звонка (не код). Фиксируем по мере
согласования в дизайн-фазе. Цель — Discord-style сетка, «один раз хорошо».

## Экран звонка — сетка участников  ✅ утверждён (2026-06-25)

**Раскладка (портрет), цель — квадратные тайлы, заполнение площади:**
- 1 участник — на весь экран
- 2 — вертикально стопкой (1 колонка × 2 ряда). НЕ горизонтальный сплит
  (узкие полосы на портрете — плохо).
- 3 — два сверху + один на всю ширину снизу
- 4 — 2×2
- 5 — 2×3, пятый на всю ширину
- 6 — 2×3

**Тайлы:** видео заполняет тайл с ОБРЕЗКОЙ (cover), края режутся (не letterbox).
Скруглённые углы. Своё превью («Вы») — обычный тайл сетки (то же видео), с
голубой акцентной рамкой. Говорящие — зелёная рамка у КАЖДОГО, кто говорит сейчас
(одновременно может гореть несколько). Динамически по активным голосам. Подписи
(ник + значок выключенного микрофона) — оверлей в нижнем углу тайла.

**Взаимодействие:**
- одиночный тап по экрану — показать/скрыть UI (подписи + панели);
  через время UI скрывается сам, остаётся только видео;
- даблтап по тайлу — фуллскрин этого участника.
- ВАЖНО: UI (chrome) рисуется ПОВЕРХ неподвижного базового слоя (видео/аватар);
  скрытие оверлея НЕ двигает контент под ним (общее для всех экранов звонка).

**Верх:** правый верхний угол — два скруглённых квадрата на подложке: быстрая
смена камеры (фронт/тыл) + Настройки. ЛЕВЫЙ верхний угол — чип суммарного
входящего трафика (↓ ~M МБ/мин), виден при показанном UI. Центр сверху — пусто.

**Низ:** панель-подложка (скруглённая «пилюля»), кнопки ПРЯМОУГОЛЬНЫЕ со
скруглением, ТОЛЬКО иконки без подписей (везде, включая экран входа). Порядок:
**Пригласить · Микрофон · Видео · Выход**.
- **Выход** — иконка ОТКРЫТОЙ ДВЕРИ (`ti-door-exit`), красная. НЕ перечёркнутая
  трубка.
- **Микрофон / Видео** — состояние видно: выключено → иконка ПЕРЕЧЁРКНУТА +
  красноватый цвет. **Тап** — вкл/выкл. **Долгий тап** — настройки (Видео →
  экран шаринга ниже; Микрофон → экран аудио, на будущее).
- **Настройки** (верхний правый угол) — отдельный экран (туда же позже: вывод
  звука/динамик, разрешение камеры, энергорежим).
- **Тех-инфо оверлей** (включается в ОБЩИХ настройках приложения): на участнике —
  пинг, разрешение/fps, битрейт видео и аудио. Всё измеримо (RTT по мешу +
  счётчики движка).

## Масштабирование сетки (модель)  ✅ согласовано (2026-06-25)

**Жёсткие ограничения (диктуют дизайн):**
- ~5 аппаратных декодеров. СВОЁ видео не декодируется (превью прямо с камеры),
  потолок живого видео = «ты + ~5 чужих».
- Полная mesh-видеосвязь = O(N²), не масштабируется → нельзя принимать видео ОТ
  ВСЕХ.

**Принцип «видимый тайл = подписка на поток»:** UI решает, кого показываем
(горстка), и только на них подписывается на видео (selective subscription).
Остальные — аудио/ничего. Выбор в UI управляет медиа-слоем.

**Тайл бывает двух видов (один компонент):**
- ВИДЕО-тайл — декодируем поток, стоит 1 декодер (дефицит ~5);
- АВАТАР-тайл — аватар + рамка говорящего, БЕЗ декодера (мик-онли, или
  видео-отправитель вне слота). Дёшево, ограничен только площадью.

**Декодеры — ПУЛ, динамически активным:** active-speaker отдаёт ~5 слотов живого
видео самым активным видео-отправителям. ≤5 камер → ВСЕ в видео, свапа нет.
Свап только при >5 камерах, и гасится:
- ГИСТЕРЕЗИС: промоут — после ~2-3с устойчивой речи; демоут — после паузы с
  cooldown ~7-10с (быстрый пинг-понг репликами сетку не двигает);
- СТАБИЛЬНЫЕ ПОЗИЦИИ: тайл не прыгает; меняется СОДЕРЖИМОЕ ячейки (видео↔аватар на
  месте), не раскладка;
- ПИННИНГ: юзер закрепляет важных (презентер) вне ротации.

**Три уровня стабильности:** членство сетки меняется медленно (зашёл/вышел/совсем
замолчал → оверфлоу); позиции стабильны; свапается только содержимое тайла.

**Зал** (молчат, ничего не шлют) → оверфлоу «+N» / список, не тайлы. Пагинация при
переполнении площади (~6-9 тайлов).

**Без режимов по числу участников.** «Сцена/трибуна» — НЕ режим, а эмерджентная
картина «мало отправителей, много зала». Единственная явная ручка — ПРАВО стать
отправителем (модерация / «поднять руку»): это access control, не режим экрана.

**Инвариант сетки (адаптив, [ADR-005](../adr/ADR-005-ui-adaptivity-platforms.md)):**
раскладка — АЛГОРИТМ, не набор макетов под устройства. `CallGrid` считает rows×cols из
`(число тайлов + aspect ratio контейнера + доступный размер)`. Один компонент
обслуживает всё: портрет (стопка/2-в-ряд), ландшафт (шире, больше колонок), планшет
(больше тайлов), overlay-мини-окно (1 активный говорящий). Никаких `if tablet` /
`if landscape` — только размер и количество на входе. Размер экрана читается ТОЛЬКО
здесь, тайл-компонент (видео/аватар) остаётся size-agnostic.
Транспорт масштабирует доставку сам (mesh → selective subscription → пир-релей/
swarm, невидимо). Swarm = и авто-оптимизация популярного потока, и движок «сцены»
(связь с Фазой F — торрент-стриминг).

## Мгновенный выход участника
По кнопке «Выход» шлётся ФИНАЛЬНЫЙ presence-пакет `PRESENCE_LEFT` → остальные
убирают тайл МГНОВЕННО, не дожидаясь TTL. Механизм уже есть (H1.0 «instant
leave»); в новом UI выход должен надёжно его дёргать (+ остановить свою отправку,
освободить декодеры).

## Экран выбора шаринга (долгий тап «Видео»)  ✅ утверждён (2026-06-25)
Открывается ДОЛГИМ тапом по кнопке Видео (обычный тап — просто вкл/выкл видео).
- Источник: Камера / Экран (сегмент-переключатель, меняет превью).
- Камера: переключатель фронтальная/тыловая (зеркалить превью фронталки).
- Живое превью.
- Разрешение и fps — показываем ТОЛЬКО доступные на устройстве (из характеристик
  камеры: `getOutputSizes` + поддерживаемые fps-диапазоны), включая выше FHD если
  камера тянет. Всё генерируется из возможностей устройства. ЭТО ЖЕ снимает баг
  «камера не стартует на неподдерживаемом размере» — невозможное просто не
  показываем.
- Битрейт — авто-рассчитывается из разрешения+fps, но РЕДАКТИРУЕМ пользователем.
- Кнопка «Показать».
- Оговорка сборки: «камера тянет 4K» ≠ «меш дотащит 4K в реалтайме» — высокие
  режимы доступны, но битрейт/устойчивость считать с оглядкой на пропускную.

## Экран приглашения в комнату (входящий)  ✅ утверждён (2026-06-25)
Это НЕ «видеозвонок», а приглашение в КОМНАТУ (room-модель): входишь и дальше САМ
решаешь, что включить — камеру, микрофон, или только слушать.
- Заголовок = имя зовущего; подпись = «приглашает в комнату» + что у НЕГО
  включено (видео/звук). Показываем как комнату: кто уже в ней («Боря и ещё N»).
  1:1 без кого-либо ещё — строки участников нет.
- До входа видео нет — аватар(ы).
- Низ — ТАКАЯ ЖЕ подложка-панель, что и в звонке (консистентность), прямоугольные
  кнопки, порядок: **Отклонить · Микрофон · Видео · Принять**. Иконки без подписей.
  Отклонить — красная `ti-x`; Принять — зелёная `ti-door-enter` (парная к выходу).
- **Микрофон/Видео на входе = ПРЕСЕТ**: в каком состоянии войдёшь (мик/камера
  вкл/выкл). По умолчанию мик вкл, видео выкл. Это и есть «выбор до входа».
- **Ожидаемый трафик** — СУММАРНЫЙ входящий от ВСЕХ в комнате, по ТЕКУЩЕМУ
  состоянию комнаты (не по дефолтам). Крупно «~M МБ/мин». Presence-маячок каждого
  несёт его текущий битрейт; до входа — снимок комнаты. «~» (адаптивно).
- Тот же суммарный входящий трафик показываем и на ГЛАВНОМ экране звонка (место
  сверху / тех-инфо — уточняется).

## Настройки по умолчанию (приложение)
Контролы качества/fps/битрейта (видео и аудио) дублируются в настройки приложения
как ДЕФОЛТЫ для всех звонков. Те же элементы, что во время звонка. Дефолт
вызывающего едет в RoomInvite (см. выше).

## Мелкие правки к утверждённому (применить при сборке)
- Главный экран: чип трафика (слева) и кнопки камера/настройки (справа) — ОДНОЙ
  высоты.
- Экран входа: убрать поясняющую подпись под панелью («мик/видео — в каком
  войдёшь») — и так понятно.

## Фуллскрин одного участника (даблтап)  ✅ утверждён (2026-06-25)
- Видео участника на весь экран (cover).
- Оверлей (chrome): СЛЕВА СВЕРХУ в одну линию — имя + чип трафика ИМЕННО этого
  участника; СПРАВА СВЕРХУ — кнопка «свернуть в сетку» (`ti-arrows-minimize`).
  Снизу — та же нижняя панель. Тап — скрыть оверлей.
- Возврат в сетку — кнопка «свернуть» + даблтап (свайп-вниз — на будущее). Без
  поясняющих надписей.

## «Вы одни в комнате»  ✅ утверждён (2026-06-25)
(= состояние сразу после входа, когда больше никого.)
- Камера ВКЛ → своё превью на весь экран. Камера ВЫКЛ → аватар по центру.
- Подсказка «Вы одни в комнате · ждём остальных» — ЧАСТЬ оверлея (chrome): по
  тапу скрывается вместе с панелью и верхними кнопками.
- Та же нижняя панель. Чипа трафика нет (входящего нет).
- **Поведение движка (важно):** один в комнате → мик/видео можно ВКЛЮЧИТЬ, но
  НИЧЕГО не кодируется и не отправляется (некому). Своё превью — напрямую с
  камеры (Camera2 → preview-surface), БЕЗ энкодера. Энкодер+отправка стартуют
  автоматически при входе первого участника (камера отдаёт в 2 сёрфейса: превью +
  энкодер). Экономит CPU/батарею. Мик при одиночестве — максимум локальный
  индикатор уровня, без кодирования/отправки. Кнопки мик/видео = ИНТЕНТ, вступает
  в силу при появлении аудитории.
