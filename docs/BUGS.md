# Известные баги

Открытые проблемы. Закрытые — в git-истории. Последний обзор: 2026-06-29.

## Звонки (видео/аудио)

### Камера
- **[ИСПРАВЛЕНО] Чёрный экран: камера не отдаёт видео на неподдерживаемом размере.**
  Корень: размер input-surface энкодера обязан быть из `StreamConfigurationMap.
  getOutputSizes` камеры — иначе `createCaptureSession` молча падает. Фикс (2026-06-29):
  `CameraCaps.resolutions` отдаёт ТОЛЬКО корзины с точным совпадением в `getOutputSizes`
  (раньше фильтр «площадь ≤ макс» предлагал, напр., 1440p ложно, хотя камера его не
  выводит). Экран «Показать видео» показывает только реально поддерживаемые размеры;
  дефолт 720p (универсален). Доп. страховка (снап `VideoSender` к ближайшему размеру)
  не нужна, пока список честный — но остаётся опцией для экзотики.
- **[редко] У одной из сторон камера вырубается / картинка пропадает** по ходу
  звонка. Причина неизвестна (камера? декодер? обрыв потока?). Лечится перезвоном.
  Нужны логи `VideoSender`/`VideoReceiver` в момент пропажи.

### Сеть
- **[ИСПРАВЛЕНО 2026-07-02] Первый звонок не доходит.** `RoomInvite`/`RoomDecline`
  были fire-and-forget → первый пакет терялся на непрогретой сессии. Переведены на
  `send_reliable` (retry-until-Ack; Ack шлётся при ДОСТАВКЕ, до ответа пользователя,
  поэтому ретрай гаснет как только звонок долетел — не «звонит вечно»). Покрыто
  loopback-тестом `room_invite_survives_packet_loss`.
- **[ИСПРАВЛЕНО 2026-07-02] Групповой инвайт не срабатывал на холодной сессии.**
  `GroupKeyRequest`/`GroupKeyReply` были fire-and-forget → первый пакет терялся, и
  приглашение молча не проходило (наблюдалось телефон↔эмулятор). Переведены на
  `send_reliable` (retry-until-Ack, идемпотентно на приёме). Покрыто loopback-тестами
  (`engine/tests/group_flow.rs`, в т.ч. под потерями). `RoomInvite` — тем же приёмом.

## К улучшению (не баг)

- **Медиа стартует на invite, а не по первому участнику.** `CallAudio` держит
  микрофон+playback всю фазу дозвона, когда играть нечего — лишний расход
  CPU/батареи/удержание мика. Чистое улучшение: стартовать медиа по первому вошедшему
  участнику (ценой ~100–200мс задержки на старте). Связано с энергомоделью.

- **Буква на аватарке — всегда первая буква ИМЕНИ человека.** Сейчас на тайле «себя»
  буква от местоимения «Вы»/«You» (→ «В»/«Y»), а у контакта без имени — от hex-ключа
  (→ «2»). Надо: своя аватарка = первая буква имени ПОЛЬЗОВАТЕЛЯ (нужен источник своего
  display-name — сейчас у `model.me` только ключ/адрес/fingerprint), контакт = имя
  (hex — только крайний фолбэк). Затрагивает `tileName`/`Avatar` в RoomCallScreen,
  GridTile/IncomingCallOverlay в CallUi, общий `SquareAvatar`.

- **Аватарки в звонке крупнее.** Текущие тайловые/alone размеры маловаты — увеличить
  (alone 104→больше, grid-аватар 64→больше), сверить с макетом call-ui.

- **Чип трафика — переделать на РЕАЛЬНЫЙ per-participant в секунду.** Сейчас грубая
  оценка суммой «~M МБ/мин» по флагам video. Надо: реальная пропускная на КАЖДОГО
  участника в КБ/с (на тайле участника — входящий от него; на своём — исходящий). Нужны
  per-peer rx/tx-счётчики в room-движке/транспорте (байты за окно). Юзер: «криво
  работает, лучше в секунду и по участникам».

- **Пинг до участника в тех-инфо чипе.** Сейчас «— ms» (заглушка): `netStats` — это
  меш-СОСЕДИ (Yggdrasil-линки), а не участники звонка (трафик к ним идёт через меш), так
  что per-participant RTT оттуда не взять. Трафик уже реальный (room-счётчики rx/tx).
  Для пинга нужен E2E RTT: тегировать keepalive-Ping таймстампом/нонсом, эхо в Pong,
  считать RTT на приёме Pong (правка протокола Ping/Pong + обе стороны должны понимать).

- **Live-переключение Opus-режима Голос↔Аудио в звонке.** Сейчас битрейт меняется на
  лету (`OPUS_SET_BITRATE`), а режим (application VOIP/AUDIO) — только со следующего
  звонка. Причина: `application` в libopus задаётся при создании энкодера, рантайм-CTL
  для него нет. Но сделать live МОЖНО без дыры: либо `OPUS_SET_SIGNAL` (VOICE/MUSIC/AUTO
  — настоящий рантайм-CTL, мягкий аналог режима), либо пересоздать ТОЛЬКО объект
  энкодера в send-треде (микросекунды, транспорт/джиттер не трогаются — это НЕ 20с-рестарт
  сессии). Добавить `target_music` (AtomicBool) рядом с `target_bitrate` в RoomCallEngine.

- **Синхронизация/надёжность звонков и сети — слабое место.** Симптомы: звонки иногда
  не доходят (RoomInvite fire-and-forget), сеть нестабильна (особенно на эмуляторе),
  холодный старт медиа медленный (видео ~2с, рестарт аудио был ~20с — cold-start
  пайплайна: capture+playback+codec+jitter+presence resync). Нужна работа над: ретраем
  приглашений, прогревом/быстрым ресинком медиа, устойчивостью presence/routing. Связано
  с [media-webrtc-parity](plans/media-webrtc-parity.md), задачами #23/#24 (мультипати/подписки).

- **Задержка видео ~2с (FHD и 4K), после перезвона лучше.** Латентность пайплайна
  (джиттер-буфер + энкодер + прогрев). Тюнинг — план [media-webrtc-parity](plans/media-webrtc-parity.md)
  (низкая задержка, адаптация). Прогрев намекает: первый старт холоднее.

- **Превью видео в настройках не работает, когда камера уже включена в звонке.**
  Аппаратное: камера single-access, её держит `VideoSender`. Сейчас — плейсхолдер.
  Можно переиспользовать ту же surface (добавить 3-й таргет в capture-сессию +
  пересоздать её, ценой кратковременного «икающего» кадра) — средняя возня, низкий
  приоритет (себя видно в сетке звонка).

- **Incoming-traffic на входящем — грубая оценка (видео≈30, аудио≈2 МБ/мин), не
  отражает реальный битрейт звонящего.** Чтобы был честным — звонящий должен слать
  свой битрейт в `RoomInvite` (добавка в протокол). Сейчас бинарно по флагу video.

- **(пост-1.0) Внешняя камера (UVC по USB-C OTG) в видео-настройках.** Android Camera2
  показывает её отдельным camera-id (`LENS_FACING_EXTERNAL`). Расширить пикер захвата:
  перечислять весь `cameraIdList` (не только фронт/тыл) + lifecycle подключения/отключения,
  как в аудио-пикере устройств. Нужна реальная UVC-камера для теста.

## Закрыто (для контекста; детали — в git)

- **Жизненный цикл комнат-звонков — РЕАЛИЗОВАНО.** Комната 1:1 постоянна
  (`dm_room_id` детерминирован); «позвонить» = войти (presence+медиа), «выйти» =
  убрать присутствие, пир остаётся. Точечные правки в коде: re-invite от того же
  пира → игнор (не рвём звонок); `Job::Leave` no-op при перезаходе (`joined` содержит
  R); `leaveRoom` шлёт `RoomDecline` ТОЛЬКО для отмены дозвона (`!peerPresent`),
  активный выход = только presence LEFT; presence-LEFT убирает тайл участника, видео
  чистится через dispose сетки (H1.2). Зависшая картинка устранена сеткой.
- **Зацикливание звука в шум — артефакт эмулятора (wontfix).** Доказано логами
  (`playback: 0 starv/5s` на обеих сторонах — наш конвейер отдаёт звук корректно);
  петля в AudioFlinger эмулятора (`FAST flag mismatch`/`mixer throttle`). На реальных
  телефонах после фикса джиттера звук чистый. Не чинить костылём под эмулятор.
