# P2P Мессенджер — Техническое задание

> Статус: черновик  
> Платформы: Android (основная), Desktop (Windows/Linux/Mac)  
> Цель: минималистичный защищённый P2P мессенджер с голосом, видео и шарингом экрана

---

## 1. Концепция

Полностью децентрализованный мессенджер без центрального сервера для передачи данных. Единственный внешний компонент — минимальный push-сервер для пробуждения приложения в фоне. Весь медиаконтент и сообщения передаются напрямую между участниками.

Дизайн вдохновлён Holo темой Android 4.x — тёмный фон, синий акцент, без лишних анимаций. Ассоциация с надёжностью и простотой.

---

## 2. Сетевой слой

### Транспорт — Yggdrasil
- Overlay mesh-сеть поверх обычного интернета
- Каждый узел получает постоянный IPv6 адрес
- Адрес детерминированно вычисляется из публичного ключа пользователя
- Встраивается в приложение как библиотека (не требует отдельной установки)
- Базовое шифрование транспортного уровня из коробки

### Push-уведомления — ntfy + UnifiedPush
- Минимальный self-hosted сервер (достаточно VPS $3-5/мес)
- Используется только для пробуждения приложения в фоне
- Содержимое уведомлений не передаётся через сервер
- Сервер знает только факт "кому-то пришло событие"

---

## 3. Криптография

### Шифрование сообщений — PyNaCl Box (Curve25519 + XSalsa20 + Poly1305)
- E2E шифрование всех сообщений и медиа
- Асимметричное шифрование между участниками
- Ключи генерируются локально при установке

### Верификация — TOFU + Fingerprint
- Trust On First Use — при первом подключении ключ сохраняется автоматически
- Fingerprint = SHA256(публичный ключ) → первые 88 бит → 8 слов BIP39
- При смене ключа — предупреждение пользователю
- Опциональная верификация: сравнить 8 слов с другом голосом или в другом канале

### Шифрование медиапотока — SRTP
- Ключи согласовываются через уже зашифрованный TCP канал
- Применяется к UDP потокам голоса и видео

## 4. Идентификация и подключение

### Генерация идентификатора
```
При установке:
→ генерируется пара ключей Curve25519
→ публичный ключ → Yggdrasil IPv6 (детерминированно)
→ SHA256(публичный ключ) → 8 слов BIP39 (fingerprint)
```

### Первое подключение
```
1. Пользователь А показывает свой QR или 8 слов
2. Пользователь Б сканирует QR или вводит слова
3. Приложение вычисляет IPv6 и публичный ключ
4. Устанавливает прямое P2P соединение через Yggdrasil
5. TOFU — сохраняет контакт, больше не нужен код
```

### Инвайт в звонок
```
→ генерируется временный токен
→ содержит публичный ключ хоста + флаг "инвайт в звонок"
→ передаётся через чат или любой другой канал
→ получатель подключается напрямую к хосту
→ дальше full mesh между всеми участниками
```

## 5. Протокол сообщений

### Каналы
- **TCP** — чат, сигнализация (установка звонка, управление)
- **UDP** — голос и видео в реальном времени

### Формат сообщений (JSON)
```json
{
  "type": "message | call_invite | call_accept | call_end | ping | file",
  "from": "публичный ключ отправителя",
  "payload": "зашифрованные данные",
  "time": 1234567890
}
```

### Статусы сообщений
- ✓ — отправлено
- ✓✓ — доставлено

## 6. Аудио

- **Кодек:** Opus (SILK для речи, CELT для остального, автопереключение)
- **Битрейт:** настраивается пользователем
- **Эхоподавление:** Android AudioEffect API (AEC)
- **Jitter buffer:** 20-50мс для сглаживания UDP

---

## 7. Видео

### Android
- **Кодек:** H.264 через MediaCodec (аппаратное кодирование/декодирование)
- **Качество:** выбирается пользователем явно (1080p60, 1080p30, 720p60, 720p30, 480p30)
- **Temporal layers:** поддержка для адаптации fps без перекодирования
- **Захват камеры:** Camera2 API
- **Захват экрана:** MediaProjection API (требует явного разрешения пользователя)
- **GPU pipeline:** MediaCodec → AHardwareBuffer (zero-copy) → Vulkan

### Desktop
- **Кодек:** H.264 SVC через FFmpeg + x264
- **Слои:** базовый (480p) + enhancement (720p) + enhancement (1080p)
- **Получатель Android:** парсит NAL units через NDK/C++, выкидывает ненужные слои, базовый слой скармливает в MediaCodec
- **Захват экрана:** нативные API платформы
- **Обёртка:** Tauri (Rust)

### Vulkan pipeline (Android, получатель)
```
MediaCodec (декодирование)
    ↓ AHardwareBuffer (zero-copy)
Vulkan compute shader:
    → YUV → RGB конвертация
    → масштабирование (если нужно)
    → композитинг UI поверх
    ↓
Swapchain → экран
```

## 8. Групповые чаты — шифрование MLS (RFC 9420)

### Почему MLS
- Общий групповой ключ — одна операция шифрования для всех участников
- Forward Secrecy — вышедший участник не читает будущие сообщения
- Post-Compromise Security — вошедший участник не читает прошлые сообщения
- Масштабируется на большие группы

### TreeKEM — структура ключей
```
        [корневой ключ]
       /               \
  [ключ AB]         [ключ CD]
  /       \         /       \
[A]       [B]     [C]       [D]
```
Каждый участник знает только свою ветку. Групповой ключ выводится из корня.

### Проблема P2P и решение
MLS требует упорядочивания Commit операций (смена состава группы). В P2P без сервера возникают конфликты при одновременных Commit.

**Решение: ntfy как Delivery Service для групп**
```
Каждая группа = отдельный топик в ntfy (случайный UUID)
→ все участники подписаны на топик
→ Commit операции публикуются в топик
→ ntfy гарантирует FIFO порядок доставки
→ содержимое зашифровано MLS — ntfy видит только байты
```

Что ntfy видит:
- Факт публикации в топик
- Размер сообщения
- Время

Что ntfy не видит:
- Участников группы
- Содержимое (зашифровано)
- Тип операции

### Библиотеки
- `openmls` (Rust) — для Desktop (Tauri)
- Через NDK для Android

## 12. Торрент-стриминг

Режим для совместного просмотра контента или трансляции экрана/камеры на группу. Выбирается отправителем вручную — не автоматически.

### Протокол
Классический BitTorrent поверх Yggdrasil IPv6. WebTorrent не используется — он создан для браузеров без прямых сокетов, в нашем случае Yggdrasil уже даёт прямые TCP/UDP соединения каждому участнику.

### Как работает
```
Отправитель:
→ нарезает живой поток на куски (размер и задержка — настройка отправителя, минимум 5 сек)
→ анонсирует куски участникам группы
→ участники скачивают напрямую друг у друга

Новый участник:
→ получает список участников группы как источники
→ подключается к ним напрямую
→ DHT не используется — список пиров из группового чата
```

### Режимы синхронизации
Выбирается отправителем при запуске:

```
Совместный просмотр (фильм, запись):
→ все ждут если кто-то буферизует
→ синхронное воспроизведение у всех

Стрим (геймплей, экран):
→ каждый воспроизводит по мере получения
→ допустимо небольшое расхождение между участниками
→ как Twitch
```

### Голосовой чат во время стриминга
Идёт параллельно прямым P2P — отдельный UDP канал. Не проходит через торрент чтобы избежать двойной задержки.

### Переключение режимов
Переключение на лету не поддерживается — требует пересинхронизации всех участников. Для смены режима отправитель перезапускает стрим.

### UI во время стриминга

**Обычный режим:**
```
↓ 2.4 МБ/с    ↑ 1.1 МБ/с
Буфер  [=========   ] 12 сек
Сидеры 👥 3          ⏱ ~8 сек
```

**Дебаг режим** (долгий тап на статистику):
```
→ список пиров с их Yggdrasil IPv6
→ детальная статистика по кускам
→ логи соединений
```
